# AI Agent 考點總覽

## 1. AI Agent 是什麼

AI Agent 是一種能根據目標規劃步驟、使用工具、觀察結果並調整行動的 AI 系統。

白話說，普通聊天機器人像「你問一句，我答一句」；AI Agent 像「你交辦一個目標，它會拆工作、查資料、選工具、做檢查，再把結果交給你」。

## 2. 核心組成

- 目標：使用者想完成什麼，例如「幫我準備 iPAS 考試」。
- 規劃器：把大目標拆成小步驟，例如查考點、整理筆記、出練習題。
- 記憶或知識：保存背景資料，或透過 RAG 查找教材。
- 工具：可呼叫搜尋、資料庫、檔案、API、RPA 或工作流程。
- 執行與觀察：執行任務後檢查結果是否符合目標。
- 風險控制：避免個資外洩、錯誤答案、越權操作與不可追蹤。

## 3. 與常見名詞比較

Chatbot：偏向對話介面，不一定會拆任務或用工具。

LLM：大型語言模型，是 Agent 可能使用的大腦，但 LLM 本身不等於 Agent。

RAG：先檢索資料再生成答案，是 Agent 可使用的一種能力或工具。

Workflow：固定流程編排，彈性較低；Agent 則可能根據目標動態決定下一步。

AutoML：自動化模型訓練與選擇，重點在機器學習流程，不等於一般任務型 Agent。

No Code / Low Code：可以拿來快速建立 Agent 原型，但正式導入仍需考慮整合、權限、資安與維運。

## 4. 實務上怎麼用

### 客服知識助理

流程：整理 FAQ 與產品文件 -> 建立知識庫 -> 用 RAG 找相關資料 -> LLM 生成回答 -> 人工審核高風險答案 -> 追蹤解決率與滿意度。

關鍵：資料要最新，回答要能追來源，涉及退款、合約、醫療或法律時要轉人工。

### 內部文件助理

流程：盤點內部文件 -> 資料分級 -> 建立權限控管 -> Agent 根據使用者權限查詢 -> 回答並附來源 -> 記錄查詢行為。

關鍵：不同職位不能看到不該看的文件，這是 Agent 導入比一般聊天更重要的地方。

### 業務報告助理

流程：連接銷售資料 -> 產生摘要 -> 找異常變化 -> 提出可能原因 -> 產生簡報草稿 -> 由業務主管確認。

關鍵：AI 可以協助整理與提醒，但業務判斷與最終決策仍需人負責。

## 5. 考試常見問法

- 問「哪一個最能描述 Agent」：選能表達目標導向、任務規劃、工具使用、回饋調整的選項。
- 問「Agent 最大風險」：注意越權操作、資料外洩、幻覺、提示注入與責任不清。
- 問「導入前優先事項」：通常先做問題定義、資料盤點、風險評估與 KPI 設定，不是先買工具。
- 問「RAG 對 Agent 的作用」：RAG 是讓 Agent 查可信資料的能力，不是保證答案完全正確。
