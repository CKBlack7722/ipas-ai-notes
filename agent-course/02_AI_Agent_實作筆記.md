# AI Agent 實作筆記：iPAS 備考助教 Agent

本範例採免 API 模擬版。也就是說，它不會真的呼叫外部大型語言模型，而是用規則與內建知識庫模擬 Agent 的運作流程。這很適合備考，因為考試重點是「理解如何規劃與導入」，不是一定要寫出商用後端。

## 1. 需求定義

目標：建立一個能協助考生複習 iPAS AI 應用規劃師的助教 Agent。

使用者：正在準備初級或中級考試的考生。

輸入：考生輸入一個問題，例如「RAG、LLM、AI Agent 差在哪裡？」

輸出：Agent 產生流程化回覆，包含考點、白話解釋、比較、風險與 KPI。

## 2. Agent 流程

### 步驟一：目標輸入

Agent 先讀取使用者問題，判斷這是一個「備考整理任務」。

考點對應：問題定義、利害關係人、AI 導入評估。

實務重點：企業導入 AI 也要先定義問題，不能只說「我們想用 AI」。

### 步驟二：任務拆解

Agent 把問題拆成小任務：

1. 找出相關概念。
2. 整理白話定義。
3. 補上類比與實務案例。
4. 指出考題常見比較。
5. 做風險檢查。

考點對應：AI 導入規劃、工作流程、人機協作。

### 步驟三：知識檢索

Agent 從內建知識庫尋找關鍵概念，例如 LLM、RAG、Agent、治理、KPI。

考點對應：RAG、Embedding、資料來源、資料品質。

實務重點：企業版通常會接文件庫、資料庫或搜尋系統。若資料過期或權限錯誤，Agent 回答就會出問題。

### 步驟四：答案生成

Agent 根據檢索到的概念產生回覆。免 API 版用規則組合答案；真實版可能使用 LLM 生成文字。

考點對應：生成式 AI、LLM、Prompt Engineering。

實務重點：Prompt 要定義角色、任務、限制、格式與資料來源要求。

### 步驟五：風險檢查

Agent 檢查是否涉及個資、機密、幻覺、偏見、提示注入與越權操作。

考點對應：AI 治理、資料隱私、安全、生成式 AI 風險管理。

實務重點：Agent 能使用工具，因此不能只管回答內容，也要管它能做什麼動作。

### 步驟六：KPI 評估

Agent 給出可衡量指標，例如答題正確率、查資料時間、人工審核通過率、錯題回收率。

考點對應：KPI、ROI、TCO、PoC、Pilot、部署監控。

實務重點：PoC 看可行性，Pilot 看真流程，正式導入才看長期 ROI 與 TCO。

## 3. 範例輸入與輸出

輸入：

```text
我不太懂 RAG、LLM、AI Agent 的差別，請用考試角度幫我整理，並提醒導入企業時要注意什麼風險。
```

輸出重點：

- LLM 是生成文字的模型。
- RAG 是先查資料再回答的方法。
- AI Agent 是會拆任務、用工具、檢查結果的系統。
- 企業風險包含資料外洩、提示注入、幻覺、越權工具呼叫與責任不清。
- 導入時要先做問題定義、資料盤點、PoC、Pilot、KPI 與治理規範。

## 4. 如果改成真 API 版要注意什麼

- 不要把 API Key 放在前端網頁，因為使用者打開開發者工具就可能看到。
- 應建立後端或 serverless function，由後端保管金鑰。
- 要記錄請求與回覆，以便稽核與改善。
- 要加入權限控管，避免 Agent 查到或操作不該碰的資料。
- 要設計失敗模式，例如模型無法回答、檢索不到資料、工具呼叫失敗時如何處理。
