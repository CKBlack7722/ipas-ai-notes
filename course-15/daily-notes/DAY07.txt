# Day 07：系統整合與部署：讓模型成為可維運服務

等級：中級
對應科目：科目一：人工智慧技術應用與規劃
評鑑對照：L21302、L21202、L21203

## 一小時安排
5 分鐘回想前日概念；30 分鐘讀知識與例子；15 分鐘做算例與測驗；10 分鐘閉卷說明並記錄錯因。首日的回想改為盤點已知概念。

## 從問題出發
模型檔能在工程師電腦執行，不等於服務可上線。真正系統還要處理輸入格式、權限、延遲、失敗重試、監控、版本與退回舊版。像一道菜做得好，仍需要完整餐廳才能穩定接客。

## 必備名詞與白話解釋
- Inference（推論）：使用已訓練模型產出預測；Training（訓練）是學習參數，像考試與讀書的差別。
- API（應用程式介面）：軟體之間的功能契約，需定輸入、輸出、錯誤碼及版本，像有規格的服務窗口。
- Container（容器）：封裝程式與依賴環境，減少「我的電腦能跑」問題，像把料理工具與食譜一起裝箱；不是資料安全的完整保證。
- 雲端部署（Cloud）：使用遠端資源，易彈性擴充但有連線、資料與費用考量；邊緣部署（Edge）靠近設備，利於低延遲與離線，受限於算力與維護；地端部署（On-premises）由組織管理自身環境，責任也較多。
- Latency（延遲）是單次完成時間；Throughput（吞吐量）是單位時間完成量；Concurrency（併發量）是同時處理中的請求數。像等餐時間、每分鐘出餐數與同時排隊人數。
- MLOps（機器學習維運）：管理資料、模型、測試、部署與監控生命週期；LLMOps（大型語言模型維運）再涵蓋提示、檢索、生成評測與詞元成本。
- Model Registry（模型登錄庫）：記錄版本、評估與核准狀態，像產品版本型錄；Rollback（回滾）是切回已知可用版。
- Data Drift（資料漂移）是輸入分布變化；Concept Drift（概念漂移）是輸入與答案關係改變。像來客年齡改變與相同年齡的購買偏好改變，不能混為一談。

## 部署流程與驗收
固定輸入契約 → 包裝服務 → 測試 → 核准版本 → 小量導流 → 看品質、延遲與錯誤 → 擴大 → 持續監控。
Blue-green（藍綠部署）保留兩套環境便於切換；Canary（金絲雀發布）先讓少量流量用新版；Shadow（影子測試）讓新版讀同樣請求但不影響正式決策。這些是降低發布風險的方法，不自動等於證明商業效益的 A/B 實驗。
例如每分鐘能處理 600 件，平均每件 0.8 秒，仍要測尖峰排隊與第 95 百分位延遲（p95），不能只報平均。成本還要含向量檢索、重試與人工覆核。

## 實務怎麼使用
產線斷網仍需即時停機，可考慮邊緣推論；跨區大量客服可考慮雲端加彈性擴充。服務失敗時要有安全降級（Fallback），例如改人工或顯示暫時無法判定；重試寫入動作要有冪等性（Idempotency，同請求重送不重複產生效果），避免同筆退款做兩次。
Agent 應使用結構化 API、明確權限、可追溯紀錄與測試環境；模型輸出先驗證格式和業務規則，再執行外部動作。

## 可能出題方向與比較陷阱
- 漂移警報是調查信號，不是立刻自動重訓的充分理由；先查資料管線、資料品質及真實成效。
- 模型準確率不包含可用性；API 成功回傳也不代表答案正確。應兼顧系統指標、模型指標與業務指標。
- 回滾模型時要確認前處理、欄位及索引版本相容，不能只換模型檔。

## 自我測驗與解析
1. 新版先接 5% 真流量並監控，屬於？A 金絲雀發布；B TF-IDF；C 全量覆蓋；D 隨機刪資料。
答案 A。它逐步承擔正式流量；B 是文字權重，C 無小量試驗，D 無法驗證發布。
2. 退款 API 重試最需要何種設計？A 不限次重複付款；B 冪等識別與交易狀態檢查；C 提高溫度；D 刪除日誌。
答案 B。相同操作不可重複造成財務效果；A 放大錯誤，C 無關交易保障，D 失去追查依據。

## 閉卷檢核
說出雲、地端、邊緣的取捨；分別提出模型、系統、業務 KPI；畫出出錯時誰接手與怎麼回滾。
